Mamba vs Transformer, from scratch

A selective state-space model (Mamba/S6), a GPT-style Transformer, RetNet-style linear attention and a Mamba–attention hybrid, all written in plain PyTorch with a hand-written Triton kernel for the selective scan. The four models are parameter-matched at about 4.7M parameters and measured for speed, memory and quality as sequences get longer. Every chart below is generated from the project's result files. Status: preliminary. Quality numbers come from one training seed with untuned learning rates; see docs/AUDIT.md for the open items.

Speed and memory

Efficiency depends on the kernel as much as the architecture

One forward pass or training step at batch size 1, until PyTorch's 2.97 GiB memory cap is hit (marked ×). Compare like with like: fused attention (PyTorch SDPA) with the fused Triton scan, or naive attention with the naive PyTorch scan. With fused kernels on both sides, attention is faster up to about 32K tokens and Mamba is faster beyond.

Systems

Six ways to compute the same recurrence

One Mamba layer's selective scan (1 sequence, 512 channels, 16 state dimensions). The PyTorch scans write every intermediate state to GPU memory; the fused Triton kernel keeps the state in registers.

Synthetic tasks

Exact recall and selective copying

Small two-layer-sized models, 3,000 training steps each. Associative recall asks the model to retrieve the values of N stored keys. Selective copying asks it to reproduce 8 tokens scattered among noise. These charts measure learning speed under a fixed budget, not capability: pure Mamba reached 52.9% on 4-pair recall when trained for 9,000 steps.

Inside the model

What the trained Mamba chooses to remember

Mamba's step size Δ decides how much of each byte enters the state. Darker means a larger Δ: the state is overwritten by this byte. Lighter means the byte is mostly skipped. Values are relative to the layer's mean. Hover a character to read its value.
